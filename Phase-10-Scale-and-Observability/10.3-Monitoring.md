## Implementation Notes

- `sentry.client.config.ts` — client-side Sentry init; session replay (5% sample, 100% on error); disabled when `NEXT_PUBLIC_SENTRY_DSN` unset; opt-out in dev
- `sentry.server.config.ts` — server-side Sentry init; 10% trace sampling in production
- `instrumentation.ts` — Next.js instrumentation hook loads Sentry on both nodejs and edge runtimes
- `components/PostHogProvider.tsx` — wraps children in PostHog provider; `autocapture: false` (manual events only, avoids PII); opt-out in dev; no-op when `NEXT_PUBLIC_POSTHOG_KEY` unset
- `app/api/health/route.ts` — `GET /api/health` returns `{status, timestamp, version, checks: {database: {ok, latencyMs}}}`; returns 503 when DB unreachable. Point UptimeRobot/BetterUptime at this endpoint.
- DB query performance: monitored via Neon console → Monitoring tab → Query insights. No code changes needed.
- **Required env vars:** `NEXT_PUBLIC_SENTRY_DSN`, `SENTRY_DSN`, `NEXT_PUBLIC_POSTHOG_KEY`, `NEXT_PUBLIC_POSTHOG_HOST`
